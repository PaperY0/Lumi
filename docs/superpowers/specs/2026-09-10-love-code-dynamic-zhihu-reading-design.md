# 恋爱法典详情页动态知乎推荐设计

## 目标

当用户打开一篇恋爱法典文章时，Lumi 在详情页推荐最相关的两条已人工筛选的知乎内容。推荐应反映当前文章的主题、标签和适用关系阶段，而不是只按一个宽泛分类随机展示。

## 范围与边界

- 仅改造恋爱法典的文章详情页。
- 仅使用本地 `curatedZhihuArticles` 中已经审核的公开元数据和外链。
- 不调用实时知乎搜索接口，不上传用户档案、聊天记录、阅读历史或文章自定义内容。
- 不改变法典首页的“精选浏览 / 搜索知乎”入口。
- 每次最多展示两条推荐；没有直接匹配时展示同分类内容作为兜底。

## 设计

新增纯函数 `getRelatedZhihuReadings(article, articles)`，返回 `{ items, reason }`。

排序按以下优先级计算：

1. 同一个知乎分类（必需）。
2. 与当前法典文章共享的标签数，更多优先。
3. 当前文章关系阶段与知乎条目 `stages` 重合，重合优先。
4. 同分时保留精选库原有顺序，保证结果稳定可预测。

如果当前文章没有可匹配的标签或阶段，仍返回同分类前两项，并明确说明这是主题相关的延伸阅读。自定义文章也可参与：它们仅以自身 `category`、`tags` 和 `stage` 进行本地匹配，绝不发送到网络。

## 界面文案

详情页继续使用“知乎延伸阅读”标题；新增“为什么推荐”短句。例如：

> 这篇法典关注冲突后的修复，因此优先选择同样讨论争吵、道歉或修复的知乎内容。

无标签重合时使用：

> 这两篇内容与当前法典属于同一关系主题，可作为延伸讨论。

保留现有来源标识、Lumi 推荐理由、知乎新标签页外链和“内容用于沟通学习与讨论引导”的边界。

## 测试与验收

- 单元测试验证：共享标签的条目优先、阶段重合用于打破标签平局、无标签时同分类兜底。
- 组件测试验证：详情页展示“为什么推荐”及最多两张知乎卡片。
- 用户验收：打开至少一篇“冲突修复”文章和一篇自定义文章，确认推荐理由随文章内容变化；点击外链可新标签页打开知乎。

## 非目标

- 不实现 AI 分析、帮我回复、模拟对话页的知乎推荐。
- 不引入收藏、阅读历史或个性化追踪。
- 不将知乎内容视为医疗、心理治疗或确定性结论。
